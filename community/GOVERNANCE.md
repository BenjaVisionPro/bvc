# Catalyst Governance

Catalyst is maintained by the project maintainers.

The governance model is intentionally simple.

The project needs clear responsibility, practical decision-making, and enough structure to keep contributions useful.

## Maintainer responsibilities

Maintainers are responsible for:

- project direction
- repository organisation
- reviewing and merging pull requests
- releases
- component boundaries
- documentation standards
- community moderation
- deciding when proposals are accepted, deferred, or declined

## Decision making

Small changes are handled through issue and pull request review.

Large changes should start with discussion before implementation.

Maintainers make final decisions when consensus is unclear or when a decision is needed to keep the project moving.

The goal is not to win arguments. The goal is to make good decisions and keep the project useful.

## Contributors

Contributors earn trust through useful, respectful, sustained contribution.

Useful contribution can include:

- code
- documentation
- examples
- testing
- bug reports
- design feedback
- reviews
- helping other developers

Influence comes from demonstrated care for the project, not volume, seniority, status, or noise.

## Becoming a maintainer

Maintainers may invite contributors to become maintainers based on:

- quality of contributions
- judgement
- reliability
- communication
- understanding of Catalyst architecture
- respect for component boundaries
- care for the community

Maintainer access is a responsibility, not a reward badge.

## Project direction

Catalyst DevKit is a platform for building Catalyst-based games and applications.

That Game: Catalyst (TGC) is the proof implementation for the Catalyst ideals.

Project direction should protect both:

- Catalyst must remain reusable beyond TGC.
- TGC must remain useful as a real proof of Catalyst capabilities.

## Component ownership

Catalyst is built from focused components.

Each component should have clear responsibility and integration points.

Maintainers may reject or defer changes that:

- blur component boundaries
- duplicate responsibility
- make the platform harder to reason about
- lock reusable Catalyst components to one game
- move authoritative server behaviour into clients without a strong reason

## Moderation

Maintainers are responsible for keeping the project spaces useful and safe.

Moderation decisions are made according to [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).

Restoration is welcome where appropriate, but project health comes first.
